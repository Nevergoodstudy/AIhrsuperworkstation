# TalentDesk v1.1.0 · 第一阶段可靠性改进

发布日期：2026-11-17（Asia/Shanghai）。本次是第一阶段改进发布；仓库已有 2026-11-15 的 v1.0.0 初始交付，本次保留原版本、标签及视频附件。

## 本次更新

- **候选人作答更可靠**：页面测评 ID 与 Cookie 授权会话同时核验；同浏览器多邀请错配返回明确冲突，暂停写入并保留草稿下载。刷新仍绑定原测评，重新打开原邀请可恢复。
- **保留人工招聘决定**：测评事件仅在拥有相应阶段归属时自动推进或恢复，避免覆盖 HR 手动设置的面试、录用等阶段；迁移记录在事务中留痕。
- **AI 结果有时效与来源**：写回前重新核验当前账号、会话和输入版本；旧结果作废，界面及 CSV 提示过期，AI 概述需要人工核验。未配置外部 AI 时关键词与人工流程仍可使用。
- **数据迁移和运行记录**：v4 新增阶段事件和分析运行表，保留旧记录；服务重启将中断的分析标为失败，避免残留“运行中”。
- **交付与恢复检查**：增加真实隔离容器的启动、重启持久化、私有原件、在线备份、新卷恢复及旧会话失效检查；同步研究、实施与部署文档和六份功能 GIF。

## 升级说明

1. 使用 Node.js 24；停止业务写入，对现有数据库和简历原件执行一致备份并校验，保存旧版本与配置。
2. 先在隔离副本启动 v1.1.0，核对登录、原件、答案、截止时间及反馈；启动自动执行事务性 v4 迁移，不伪造历史阶段。
3. 验证后升级单个正式实例。回滚需要旧版本与升级前的兼容快照，恢复至新目录或新卷并重新核对快照之后的删除和权限变更。
4. 旧候选人标签页从原邀请重新进入；自定义客户端需在受保护门户请求同时发送授权 Cookie 与 X-Exam-Id。CSV 增加“分析状态”列；旧版无来源分析需重新运行。

## 使用边界

仍为单企业、单实例、SQLite 与本地持久化磁盘。正式域名 HTTPS / Caddy、浏览器 Secure Cookie、企业 SMTP 收件、外部 AI、异地备份取回、实际 RPO / RTO 和生产回滚仍需实际环境验收。本次发布不代表已正式上线。

阶段事件已采集，时间线界面、负责人待办、独立评审、分页统计、多租户和高可用不在本版本内。AI 与关键词覆盖率均不替代招聘决定。
