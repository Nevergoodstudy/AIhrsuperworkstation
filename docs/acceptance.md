## 已实现的业务交付范围

| 能力 | 当前交付与实际边界 |
| --- | --- |
| 真实数据与身份 | 空库启动，无默认账号或演示数据；员工、候选人独立服务端会话；账号管理、强制改密和停用 |
| 招聘资料 | 岗位、题库、测评方案、候选人资料、授权记录、候选人阶段；PDF/DOCX/TXT 解析与私有原件下载 |
| 招聘协作 | 服务端逐请求授权；部门名称精确匹配岗位部门；部门不获取联系方式、完整简历或原件；内部共享题库可读，题目不按部门隔离 |
| 专属邀请 | 随机 token 仅存摘要，仅创建时显示原链接；有效状态下可以再次进入；遗失时撤销重发，不是一次打开即失效 |
| 候选人作答 | 独立入口、规则与同意、服务端计时、自动保存、版本冲突拒绝、截止时只提交服务端收到的答案、题目与 rubric 快照 |
| 人工评价 | 逐题评分与内部建议；HR 发布/撤回候选人可见反馈；发布时锁定评分；人工评分计算结果，系统不自动录用或淘汰 |
| 辅助分析 | 岗位关键词覆盖及原文证据；可选外部 AI 整理逐字核验的证据；覆盖率不是录用分，AI 不代替人工决策 |
| 数据处理 | CSV 公式注入防护；候选人连带删除答卷/复核/原件；文件清理持久重试；历史备份需依留存策略到期处理 |
| 运行维护 | health/ready、优雅退出、在线备份/校验/新目录恢复；Docker/Caddy/持久化卷/备份任务配置及升级回滚手册已提供 |

解析限制：每份文件不超过 10 MB，PDF 不超过 100 页，DOCX 不超过 2,000 个条目和 30 MB 解压内容；worker 限时 25 秒、最多并发两份。扫描件没有 OCR。部门答卷中的邮箱和电话使用规则脱敏，无法识别所有个人信息，业务人员仍需检查正文。

## 尚未验证或不在本版范围内

- 当前开发机没有 Docker。本轮镜像构建、Compose 配置及隔离容器恢复已在上述远端 CI 实跑通过；完整 Caddy / HTTPS、正式配置和异地副本的恢复仍待服务器验收。
- 未完成真实域名和服务器的 HTTPS、Secure Cookie、代理来源、限速与外部网络验收。
- 没有正式 SMTP 收件箱送达记录。accepted 只表示发送服务接受；需要检查收件箱、垃圾箱、退信与服务商投递记录。
- 没有外部 AI 服务验收记录。未配置时人工招聘流程仍可使用；启用前需要企业确认候选人授权、传输范围与服务商配置。
- 未进行容量/压力测试、渗透测试、跨浏览器兼容矩阵、故障切换或生产级 RPO/RTO 测量；不能承诺 SLA 或并发人数。
- 本版是单企业、单应用实例；没有多租户、多实例高可用、SSO/MFA、OCR、视频监考或自动录用淘汰。浏览器切屏事件不构成作弊判定。
- 管理界面展示最近 200 条审计；长期归档、备份留存、加密异地保存和删除请求管理需由企业明确责任与实际安排。

## 正式环境上线签收

以下项目均需在正式或与正式配置一致的隔离环境执行，并记录实际日期、执行人、版本/镜像标识及证据。当前未勾选项表示待验收，不能由本机测试结果自动替代。

- [ ] **服务器与 HTTPS**：真实域名解析正确，80/443 可达；Compose 配置校验、镜像构建和容器健康通过；应用端口不对外暴露；生产 APP_URL 与 SITE_ADDRESS 一致，证书及 Secure Cookie 正常。
- [ ] **空库与实际账号**：可信终端创建企业管理员；无默认或测试账号；首次改密、HR/部门建号、停用、重置与会话失效符合预期；至少一名有效管理员保留。
- [ ] **权限与部门边界**：使用 HR 和两个不同部门账号，验证岗位/候选人/测评范围、原件与联系方式保护、共享题库边界；确认部门精确命名规则。
- [ ] **真实授权测试简历**：使用已获授权的测试材料验证实际文件上传、解析、人工核实、私有下载、候选人阶段和 CSV；按约定完成测试资料删除。
- [ ] **外部候选人链路**：通过手机与办公网络外的实际链接完成同意、开始、保存刷新、断网提示、截止和提交；验证过期/撤销邀请不能进入，且不会向候选人返回 rubric 或内部评语。
- [ ] **人工复核与反馈**：逐题打分、多人复核、冲突提示、发布、锁定和撤回正常；候选人仅看到已发布反馈；业务负责人确认评分要点和操作流程。
- [ ] **重启与持久化**：重启正式部署的应用容器后，账号、岗位、原件和已保存答卷仍在；截止时间不重置；无丢失或重复提交。
- [ ] **实际备份恢复演练**：运行正式卷备份与校验，验证加密异地副本；恢复到新卷并保留旧卷，核对原件、业务记录和会话失效；重新应用快照后的删除、停用、改密和邀请撤销；记录恢复耗时与可接受数据损失。
- [ ] **监控与维护责任**：落实 HTTPS/健康/磁盘/备份失败告警和日志轮转；明确业务、系统维护、备份恢复负责人、维护窗口及升级回滚方式。
- [ ] **邮件（启用时必验）**：用企业 SMTP TLS 发送到实际收件箱，核实发件人、链接域名、入箱与失败提示；不启用时由负责人确认采用手动分享邀请，并记录为不适用。
- [ ] **外部 AI（启用时必验）**：核实 HTTPS 服务、模型、授权、超时/失败处理和原文证据，不把模型输出当作录用决定；不启用时确认人工流程可用，并记录为不适用。
- [ ] **业务试运行与签收**：以企业约定的试运行规模完成一次实际招聘闭环，处理发现的问题；确认本版能力边界、数据留存和人员交接，再决定是否开放正式业务。
