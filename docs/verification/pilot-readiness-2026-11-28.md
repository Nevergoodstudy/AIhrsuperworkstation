# 岗位评审试点验收记录

2026-11-28（中国标准时间）

## 功能和安全回归

- HR 可按岗位为新邀请预设负责人、必要评审人和复核时限。邀请、题目快照及评审安排同事务建立。正式提交或自动关卷后按约定时长计算复核期限。
- 候选人可在开考前查看应聘岗位和求助说明。HR 手动分享邀请后可留痕。开考前调整作答时长时，旧页面需要先确认新时长。开考后的服务端截止时间固定。
- 「我的待办」按复核期限与测评编号分页，授权条件在查询内执行。工作台摘要缩减候选人字段和测评反馈字段。完整材料仍从授权详情读取。
- 已发布结果首次成功返回时，按测评和反馈版本记录一次访问时间。该记录可与 HR 的实际发送和候选人确认对账。
- SMTP 拒收与结果未知分别记录。未知状态须核实后才能重试。进行中的发送和已被 SMTP 接受的邀请拒绝重复发送。按岗位导出试点 CSV，保留首次与当前期限、首次决定、催办、通知、访问和候选人确认时间。
- 本地通过 41 项服务端测试、7 项浏览器测试、生产构建及 npm 依赖审计。浏览器回归包括 390 像素宽度下通过键盘开始、填写并确认保存、刷新恢复、提交和打开结果，以及阶段切换后的焦点校验。

## 本机容量对照

Apple M4 Pro / 24 GiB，macOS 本机，Node.js 24.22.1 / SQLite 3.53.4。使用独立临时数据，按 1,000 份候选资料 / 20 个活跃作答会话和 10,000 / 100 两档测试。每档各三轮，每轮约 15 秒，每轮每个会话保存 11 次。并行读取员工工作区、提交约 8 KiB 的单题答案、解析合成简历并生成在线快照。每轮恢复快照并核对所有活跃答卷的最终内容和版本。响应大小为解码后的 JSON 字节数。以下给出三轮范围。

| 档位 | 列表方式 | 工作区 P95 | 保存 P95 | 工作区 JSON | 错误 / 版本或内容不一致 |
| --- | --- | --- | --- | --- | --- |
| 1,000 / 20 | 原完整响应 | 48.77–50.57 ms | 52.37–56.01 ms | 702–711 kB | 0 / 0 |
| 1,000 / 20 | 工作台摘要 | 39.63–43.27 ms | 42.21–46.21 ms | 280–281 kB | 0 / 0 |
| 10,000 / 100 | 原完整响应 | 272.64–294.42 ms | 270.11–281.13 ms | 6.90–6.91 MB | 0 / 0 |
| 10,000 / 100 | 工作台摘要 | 196.18–208.87 ms | 191.42–204.06 ms | 2.72 MB | 0 / 0 |

摘要将第二档响应缩减约 61%。目标服务器上的 15 分钟稳态与峰值、多部门实测、代理链和故障告警仍需用实际配置签收。

## 容器、迁移与部署条件

本机构建 Linux ARM64 生产镜像，容器验收通过健康检查、非 root 与只读根文件系统、重启持久化、在线备份及新卷恢复。另用合成 v5 数据执行 v6 升级，并用升级前快照和 v5 旧镜像在独立目录回滚。对账确认答卷内容与版本、既有评审任务和简历原件保留。冻结的 v3 数据库也通过了向 v6 迁移与重复启动验证。

企业试点需要实际使用环境、目标岗位和人员，以及企业基线数据，才能签收公网候选人体验、真实通知、加密异地恢复、按期决策率、催办量和反馈实际可达率。部署与回滚命令参见 [运维手册](../operations.md#6-升级与回滚)。

## Docker Desktop 复验

- 生产镜像及 Compose 配置校验通过。Caddy 使用本地 CA 验证 HTTPS，静态资源、就绪检查和登录后工作区均可访问。检查了 HSTS 和员工会话的 Secure、HttpOnly、SameSite=Strict 属性。SMTP 和外部 AI 均关闭。
- Node.js 24.22.3 容器内通过 41 项服务端测试和 7 项 Chromium 浏览器测试。服务端回归核对了试点 CSV 的最近反馈撤回时间，以及撤回后当前发布、通知、访问和确认列为空的行为。
- 非 root、只读应用容器通过重启、在线备份和新卷恢复。恢复后核对原件、答卷和旧会话失效。合成资料的并发删除演练确认失败快照被清理、上次有效备份可继续使用，且恢复后可重放删除。

[容量脚本](../../scripts/capacity-pilot.mjs) 从两个档位分别创建合成岗位、候选资料与活跃答卷，并行测量工作区摘要、自动保存、简历解析和在线快照。每轮核对服务端确认的最终答卷版本和答案，恢复后按快照自身记录的版本核对答案。脚本逐轮输出 JSON，每档默认三轮，每轮约 15 分钟。

本次在 Docker Desktop Linux ARM64 环境测量，虚拟机配置为 12 vCPU、约 7.75 GiB 内存，Node.js 24.22.3 / SQLite 3.54.1。基于 `07a04a1` 的生产镜像，每档各三轮、每轮约 91 秒。六轮均成功恢复快照，23,400 次自动保存无请求错误，最终答卷版本和内容与服务端确认记录一致。更新 CSV 后的镜像也通过了两个档位的快速检查。

| 候选资料 / 活跃作答会话 | 工作区 P95 | 自动保存 P95 | 工作区 JSON | 在线快照耗时 |
| --- | --- | --- | --- | --- |
| 1,000 / 20 | 37.66–40.78 ms | 39.77–45.12 ms | 285,956 字节 | 37.04–65.82 ms |
| 10,000 / 100 | 186.29–207.81 ms | 176.34–199.11 ms | 2,754,175 字节 | 285.91–291.37 ms |

首档达到计划设定的工作区 P95 800 ms、保存 P95 1 秒门槛。目标服务器仍需实测 15 分钟稳态和峰值，以及代理链、SQLite 写等待和故障告警。

在仓库根目录可用生产镜像运行快速检查。脚本复用仓库测试数据生成器，临时服务及备份存放在容器的 `/tmp`。

```sh
docker build -t talentdesk:pilot .
docker run --rm --network none --no-healthcheck --read-only \
  --tmpfs /tmp:rw,size=512m \
  --mount "type=bind,source=$PWD/tests,target=/app/tests,readonly" \
  --entrypoint node talentdesk:pilot scripts/capacity-pilot.mjs --seconds 5 --rounds 1
```
